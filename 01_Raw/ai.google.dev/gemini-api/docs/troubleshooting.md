# מדריך לפתרון בעיות

המדריך הזה יעזור לכם לאבחן ולפתור בעיות נפוצות שמתעוררות כשקוראים ל-Gemini API. יכול להיות שתיתקלו בבעיות בשירות הקצה העורפי של Gemini API או בערכות ה-SDK של הלקוח. ערכות ה-SDK ללקוח שלנו הן קוד פתוח במאגרים הבאים:

- [python-genai](https://github.com/googleapis/python-genai)
- [js-genai](https://github.com/googleapis/js-genai)
- [go-genai](https://github.com/googleapis/go-genai)

אם נתקלתם בבעיות במפתח API, ודאו שהגדרתם את מפתח ה-API בצורה נכונה לפי [מדריך ההגדרה של מפתח API](https://ai.google.dev/gemini-api/docs/api-key?hl=he).

## קודי שגיאה

רשימה מלאה של כל קודי השגיאה, כולל קודי סטטוס של HTTP, קודים של חסימת יצירה וקודי שגיאה של תוכן, מפורטת בדף [שגיאות ב-API](https://ai.google.dev/gemini-api/docs/api-errors?hl=he).

## אסטרטגיה של ניסיון חוזר

אם קיבלתם שגיאה שמציינת שצריך לנסות שוב את הבקשה (כמו `429 RESOURCE_EXHAUSTED` או `503 UNAVAILABLE`), מומלץ להטמיע אסטרטגיית השהיה מעריכית לפני ניסיון חוזר (exponential backoff). המשמעות היא שצריך להמתין זמן קצר לפני הניסיון החוזר הראשון, ואז להגדיל בהדרגה את זמן ההמתנה בין הניסיונות החוזרים הבאים.

ערכות ה-SDK הרשמיות של הלקוח ל-Gemini API, כמו [Python SDK](https://github.com/googleapis/python-genai), כוללות כברירת מחדל לוגיקה של ניסיון חוזר עם השהיה מעריכית לפני ניסיון חוזר (exponential backoff) לטיפול בשגיאות זמניות כמו זמן קצוב לתפוגה, בעיות ברשת והגבלת קצב של יצירת בקשות (קודי סטטוס `429` ו-`5xx`). לדוגמה, Python SDK מנסה שוב באופן אוטומטי לתקן שגיאות זמניות עד ארבע פעמים, עם השהיה ראשונית של שנייה אחת בערך והשהיה מקסימלית של 60 שניות.

אם אתם שולחים בקשות ישירות ל-API בארכיטקטורת REST או משנים את הלוגיקה של ניסיון חוזר, כדאי לפעול לפי השיטות המומלצות הבאות כדי להגדיל את הסיכוי שהבקשה תצליח ולמנוע עומס יתר על השירות:

- **השתמשו בהשהיה מעריכית לפני ניסיון חוזר (exponential backoff):** המתינו זמן קצר לפני הניסיון החוזר הראשון (לדוגמה, שנייה אחת), ואז הגדילו את ההשהיה באופן מעריכי (לדוגמה, 2 שניות, 4 שניות, 8 שניות).
- **הוספת ריצוד:** מוסיפים "ריצוד" אקראי להשהיה כדי למנוע מכל הלקוחות לנסות שוב בדיוק באותו הזמן.
- **ניסיון חוזר בשגיאות ספציפיות:** נסו שוב רק בשגיאות זמניות (כמו `429`,‏ `408` או `5xx`). אל תנסו שוב בשגיאות בצד הלקוח (כמו `400`,‏ `402` או `403`), כי הן מצביעות על בעיות כמו מפתחות API לא חוקיים, קרדיטים שנגמרו בתשלום מראש או תחביר שגוי.
- **הגדרת מספר מקסימלי של ניסיונות חוזרים:** כדי למנוע לולאות אינסופיות, כדאי להגדיר מספר מקסימלי של ניסיונות חוזרים.

## זמן אחזור ארוך יותר או שימוש רב יותר בטוקנים עם מודלים של חשיבה

השהיה גבוהה יותר או שימוש באסימונים מתרחשים לעיתים קרובות כי במודלים של Gemini 3.x מופעלת חשיבה כברירת מחדל. גם מודלים של Gemini 2.5 שהוצאו משימוש משתמשים בחשיבה כברירת מחדל.

מודלים של חשיבה יוצרים טוקנים פנימיים של הסקת מסקנות כדי לשפר את האיכות. תהליך החשיבה הזה מגדיל את זמן האחזור של התשובה ואת צריכת הטוקנים הכוללת.

אם אתם מעדיפים זמן אחזור קצר יותר או רוצים לצמצם את העלויות, אתם יכולים להוריד את רמת החשיבה או להשבית את החשיבה.

פרטים על ההגדרה ודוגמאות קוד מופיעים ב[מדריך לתכנון](https://ai.google.dev/gemini-api/docs/thinking?hl=he#thinking-levels).

## בעיות בטיחות

אם אתם רואים שהנחיה נחסמה בגלל הגדרת בטיחות בקריאה ל-API, בדקו את ההנחיה בהתאם למסננים שהגדרתם בקריאה ל-API.

אם מופיע הסמל `BlockedReason.OTHER`, יכול להיות שהשאילתה או התשובה מפרות את [התנאים וההגבלות](https://ai.google.dev/terms?hl=he) או שהן לא נתמכות מסיבה אחרת.

## בעיה בהקראה

אם אתם רואים שהמודל מפסיק ליצור פלט בגלל הסיבה RECITATION, זה אומר שהפלט מהמודל עשוי להיות דומה לנתונים מסוימים. כדי לפתור את הבעיה, נסו להפוך את ההנחיה או ההקשר לייחודיים ככל האפשר ולהשתמש בטמפרטורה גבוהה יותר.

## מפתחות API חסומים או לא תקינים

בקטע הזה מוסבר איך לבדוק אם מפתח ה-API של Gemini חסום ומה לעשות במקרה כזה.

### למה מפתחות נחסמים

זיהינו נקודת חולשה שבה חלק ממפתחות ה-API נחשפו באופן ציבורי. כדי להגן על הנתונים שלכם ולמנוע גישה לא מורשית, חסמנו באופן יזום את הגישה של המפתחות שהודלפו ל-Gemini API.

### אישור אם המפתחות מושפעים

אם ידוע שהמפתח שלכם הודלף, לא תוכלו יותר להשתמש במפתח הזה עם Gemini API. אתם יכולים להשתמש ב-[Google AI Studio](https://ai.google.dev/gemini-api/docs/api-key?hl=he) כדי לבדוק אם אחד ממפתחות ה-API שלכם חסום לשליחת קריאות ל-Gemini API, וליצור מפתחות חדשים. יכול להיות שתוצג גם השגיאה הבאה כשמנסים להשתמש במפתחות האלה:

```
Your API key was reported as leaked. Please use another API key.
```

### פעולה למפתחות API חסומים

מומלץ ליצור מפתחות API חדשים לשילובים של Gemini API באמצעות [Google AI Studio](https://ai.google.dev/gemini-api/docs/api-key?hl=he). מומלץ מאוד לבדוק את שיטות הניהול של מפתחות ה-API כדי לוודא שהמפתחות החדשים מאובטחים ולא חשופים באופן ציבורי.

### חיובים לא צפויים בגלל נקודת חולשה

[שליחת בקשת תמיכה בנושא חיוב](https://console.cloud.google.com/support/chat?hl=he).
צוות החיוב שלנו מטפל בבעיה, ונעדכן אותך בהקדם האפשרי.

### אמצעי האבטחה של Google למפתחות שדלפו

**איך Google תעזור לי להגן על החשבון מפני חריגה מהעלויות וניצול לרעה במקרה של דליפת מפתחות ה-API?**

- אנחנו עוברים להנפקת מפתחות API כשאתם מבקשים מפתח חדש באמצעות [Google AI Studio](https://ai.google.dev/gemini-api/docs/api-key?hl=he). כברירת מחדל, המפתחות האלה יהיו מוגבלים רק ל-Google AI Studio ולא יקבלו מפתחות משירותים אחרים.
  כך תוכלו למנוע שימוש לא מכוון במפתחות שונים.
- כברירת מחדל, אנחנו חוסמים מפתחות API שדלפו ומשמשים ל-Gemini API, כדי למנוע ניצול לרעה של העלויות ושל נתוני האפליקציה.
- תוכלו למצוא את הסטטוס של מפתחות ה-API ב-[Google AI Studio](https://ai.google.dev/gemini-api/docs/api-key?hl=he). אם נזהה שמפתחות ה-API שלכם דלפו, נעדכן אתכם באופן יזום כדי שתוכלו לפעול באופן מיידי.
