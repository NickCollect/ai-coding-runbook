# Origin API Changelog

The Origin API is in Early Beta and subject to change. Review the [OpenAPI specification](https://cursor.com/docs/api/origin/openapi.yaml) when updating an integration.

Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: **Breaking**, **Deprecated**, **Added**, **Changed**, or **Removed**. Breaking and deprecated changes include migration guidance inline. The [Origin API reference](https://cursor.com/docs/api/origin.md) always reflects the latest synced state.

## September 27, 2026

- **Changed.** A `pageSize` sent with a `pageToken` applies to that page, and a follow-up request that omits `pageSize` keeps the previous page size, on [List App Installation Repositories](https://cursor.com/docs/api/origin/reference/list-app-installation-repositories.md), [List Branches](https://cursor.com/docs/api/origin/reference/list-branches.md), [List Check Run Annotations](https://cursor.com/docs/api/origin/reference/list-check-run-annotations.md), [List Check Runs For Commit](https://cursor.com/docs/api/origin/reference/list-check-runs-for-commit.md), [List Check Runs For Suite](https://cursor.com/docs/api/origin/reference/list-check-runs-for-suite.md), [List Check Suites For Commit](https://cursor.com/docs/api/origin/reference/list-check-suites-for-commit.md), [List Commit Files](https://cursor.com/docs/api/origin/reference/list-commit-files.md), [List Comparison Files](https://cursor.com/docs/api/origin/reference/list-comparison-files.md), [List Namespace Grants](https://cursor.com/docs/api/origin/reference/list-namespace-grants.md), [List Namespaces](https://cursor.com/docs/api/origin/reference/list-namespaces.md), [List Pull Request Files](https://cursor.com/docs/api/origin/reference/list-pull-request-files.md), [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md), [List Repos](https://cursor.com/docs/api/origin/reference/list-repos.md), and [List Repository Grants](https://cursor.com/docs/api/origin/reference/list-repository-grants.md). List Commit Files and List Comparison Files no longer reject a follow-up `pageSize` that differs from the first request's with `InvalidArgument` (HTTP 400), and the other endpoints no longer ignore it. Everything else a page token is bound to, such as the repository, filters, and pull request version, still has to match.

## September 26, 2026

- **Changed.** [Merge Pull Request](https://cursor.com/docs/api/origin/reference/merge-pull-request.md) returns `Aborted` (HTTP 409 Conflict) instead of `InvalidArgument` (HTTP 400) when the pull request's head branch has moved past the head of its latest `version`, for example because a push landed that Origin had not yet recorded as a new version. That is the same answer as a stale `expectedHeadSha`. Nothing merges in either case; retry after [Get Pull Request](https://cursor.com/docs/api/origin/reference/get-pull-request.md) reports the new head in `version.headSha`.

## September 25, 2026

- **Breaking.** Comment thread and review version references no longer carry `createdAt`; they hold only the version's `number`, `headSha`, and `baseSha`. This covers `thread.version` on [List Pull Request Comments](https://cursor.com/docs/api/origin/reference/list-pull-request-comments.md), [Get Pull Request Comment](https://cursor.com/docs/api/origin/reference/get-pull-request-comment.md), [Create Pull Request Comment](https://cursor.com/docs/api/origin/reference/create-pull-request-comment.md), and [Update Pull Request Comment](https://cursor.com/docs/api/origin/reference/update-pull-request-comment.md), `version` on [Update Pull Request Thread](https://cursor.com/docs/api/origin/reference/update-pull-request-thread.md), `pullRequestVersion` on [List Pull Request Reviews](https://cursor.com/docs/api/origin/reference/list-pull-request-reviews.md), [Create Pull Request Review](https://cursor.com/docs/api/origin/reference/create-pull-request-review.md), [Update Pull Request Review](https://cursor.com/docs/api/origin/reference/update-pull-request-review.md), and [Dismiss Pull Request Review](https://cursor.com/docs/api/origin/reference/dismiss-pull-request-review.md), and the same fields in the [`pull_request.comment.created`](https://cursor.com/docs/api/origin/reference/pull-request-comment.md) and [`pull_request.review.*`](https://cursor.com/docs/api/origin/reference/pull-request-review-events.md) payloads. Migration: wherever your integration read `createdAt` from a thread or review version, read it from `version` on [Get Pull Request](https://cursor.com/docs/api/origin/reference/get-pull-request.md) or on the [`pull_request.*` lifecycle payload](https://cursor.com/docs/api/origin/reference/pull-request-events.md) that recorded that version, matching on `number`.
- **Added.** Pull request versions carry `potentialMergeCommit`, Origin's test merge of that version: `state` is `prepared`, `merge_conflict`, or `unknown`, and a `prepared` merge adds the merge commit's `sha` and the base branch tip `baseSha` it was built on. Returned in `version` by [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md), [Get Pull Request](https://cursor.com/docs/api/origin/reference/get-pull-request.md), [Create Pull Request](https://cursor.com/docs/api/origin/reference/create-pull-request.md), [Update Pull Request](https://cursor.com/docs/api/origin/reference/update-pull-request.md), and [Merge Pull Request](https://cursor.com/docs/api/origin/reference/merge-pull-request.md), and carried by the [`pull_request.*` lifecycle payloads](https://cursor.com/docs/api/origin/reference/pull-request-events.md), so a webhook receiver learns the merge preview without calling [Get Git Ref](https://cursor.com/docs/api/origin/reference/get-git-ref.md). An event carries the value as of its emission, so treat `unknown` as not yet known and re-read the pull request.
- **Added.** [Create Installation User Token](https://cursor.com/docs/api/origin/reference/create-installation-user-token.md) mints an installation user token that acts on behalf of an eligible namespace member: `POST /v1/origin/app/installations/{installationId}/user_access_tokens`. Requires an app JWT and an installation granted [`namespace:user_tokens:write`](https://cursor.com/docs/api/origin/reference/scopes.md). Name the user with `userId` or `userEmail`; optional `scopes` and `repositoryIds` narrow access. The token expires within 15 minutes and never outlives the app JWT.
- **Added.** User actors can include `performedVia.app` with the app's `id` and optional `displayName` when an app acted on the user's behalf. The field is absent for direct user actions and can be absent when delegation data is unavailable. See [Acting on behalf of users](https://cursor.com/docs/api/origin/acting-as-users.md).
- **Added.** [List Commits](https://cursor.com/docs/api/origin/reference/list-commits.md) accepts `authorEmails` and `committerEmails` filters, with up to 100 distinct emails each. Matching ignores case and surrounding whitespace; a commit must match both lists when both are set. A filtered page can be empty and still have a `nextPageToken`, so keep paging until the token is empty.
- **Changed.** A cancelled check run no longer displaces a passing result. A `completed` post with the conclusion `cancelled` to a run that is `completed` with `success`, `neutral`, or `skipped` is ignored as stale whatever its `externalUpdatedAt`, so [Post Check Run](https://cursor.com/docs/api/origin/reference/post-check-run.md) and [Batch Upsert Check Runs](https://cursor.com/docs/api/origin/reference/batch-upsert-check-runs.md) answer `200` with the stored run and the `outcome` `ignored_stale`. A cancellation posted as a new run attempt or suite attempt ranks below the passing attempt instead, so [List Check Runs For Commit](https://cursor.com/docs/api/origin/reference/list-check-runs-for-commit.md), [List Check Suites For Commit](https://cursor.com/docs/api/origin/reference/list-check-suites-for-commit.md), [List Check Runs For Suite](https://cursor.com/docs/api/origin/reference/list-check-runs-for-suite.md), and [Get Pull Request Mergeability](https://cursor.com/docs/api/origin/reference/get-pull-request-mergeability.md) keep reporting the pass. A newer failure still replaces a pass, and a cancellation still applies over a failing or pending run; [Attempts and the current attempt](https://cursor.com/docs/api/origin/reference/attempts-and-the-current-attempt.md) has the full rule.

## September 24, 2026

- **Added.** [List Namespaces](https://cursor.com/docs/api/origin/reference/list-namespaces.md) lists the namespaces you can list repositories in, ordered by slug: `GET /v1/origin/namespaces`. The candidates are your teams' namespaces, your personal namespace, and the namespaces holding repositories you were granted, and only those on which you hold [`namespace:repositories:read`](https://cursor.com/docs/api/origin/reference/scopes.md) are returned, so each `namespace.slug` is a valid `ownerSlug` for [List Repos](https://cursor.com/docs/api/origin/reference/list-repos.md). Each entry's `viewerCanCreateRepositories` says whether [Create Repo](https://cursor.com/docs/api/origin/reference/create-repo.md) in that namespace would pass authorization and the owner's plan and settings checks for you. Pages hold 30 namespaces by default and at most 100. Requires a Cursor user credential and no scope, and costs 1 point; app tokens, installation tokens, and service accounts receive `PermissionDenied` (HTTP 403).

## September 23, 2026

- **Changed.** Reopening a pull request through [Update Pull Request](https://cursor.com/docs/api/origin/reference/update-pull-request.md) records a new `version` when the head moved while the pull request was closed, and sends [`pull_request.head_ref.pushed`](https://cursor.com/docs/api/origin/reference/events.md). The pull request previously kept the head it had when it was closed until the branch was pushed again. The recorded version carries its own `headSha`, `baseSha`, and diff stats, the same shape a push records. Merged pull requests are unaffected.
- **Changed.** An abbreviated commit SHA sent to [Get Commit](https://cursor.com/docs/api/origin/reference/get-commit.md) or [List Commit Files](https://cursor.com/docs/api/origin/reference/list-commit-files.md) resolves the same way as on [Get Git Commit](https://cursor.com/docs/api/origin/reference/get-git-commit.md): among commit objects only, so a prefix that names exactly one commit resolves even when a blob or tree in the repository shares it. The [September 22](https://cursor.com/docs/api/origin/changelog.md#sep-22-2026) entry named Get Git Commit only. [Get Blob](https://cursor.com/docs/api/origin/reference/get-blob.md) and [Get Tag](https://cursor.com/docs/api/origin/reference/get-tag.md) are unchanged.

## September 22, 2026

### Apps and installations

- **Changed.** [Create Installation Access Token](https://cursor.com/docs/api/origin/reference/create-installation-access-token.md) states that a token expires after at most 15 minutes and never later than the app JWT that requested it. Read `expiresAt` on the response and mint a new token when it passes rather than assuming a duration.

### Pull requests

- **Breaking.** [Create Pull Request](https://cursor.com/docs/api/origin/reference/create-pull-request.md) no longer accepts `parentPullNumber`. A request that carries it returns `InvalidArgument` (HTTP 400) naming `parent_pull_number` rather than creating the pull request, so a client that kept sending it fails loudly instead of silently losing the stack parent. Migration: send `parentPullRequest` with a `number` member wherever your integration sent `parentPullNumber`.
- **Added.** [Delete Pull Request Comment](https://cursor.com/docs/api/origin/reference/delete-pull-request-comment.md) deletes a pull request comment by its Origin id: `DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/comments/{commentId}`. The comment's author can always delete it, and any other caller must hold write access to the repository through [`repository:contents:write`](https://cursor.com/docs/api/origin/reference/scopes.md) or receives `PermissionDenied` (HTTP 403). Deleting the last comment of a thread removes the thread, deleting any other comment leaves the thread in place, and the comment's reactions and edit history go with it. An unknown or already-deleted id returns `404`. Requires [`repository:pull_requests:reviews:write`](https://cursor.com/docs/api/origin/reference/scopes.md) and costs 5 points.
- **Added.** Pull request responses carry a `stack` object holding the stack's `id` and the `parentPullRequest` this pull request is stacked on, absent when the pull request is not part of a stack and carrying no `parentPullRequest` on the root. Returned by [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md), [Get Pull Request](https://cursor.com/docs/api/origin/reference/get-pull-request.md), [Create Pull Request](https://cursor.com/docs/api/origin/reference/create-pull-request.md), [Update Pull Request](https://cursor.com/docs/api/origin/reference/update-pull-request.md), and [Merge Pull Request](https://cursor.com/docs/api/origin/reference/merge-pull-request.md), and carried by every [`pull_request.*` payload](https://cursor.com/docs/api/origin/reference/pull-request-events.md). A delivered `stack` reflects the topology as of the event that carried it.
- **Added.** [Create Pull Request](https://cursor.com/docs/api/origin/reference/create-pull-request.md) and [Update Pull Request](https://cursor.com/docs/api/origin/reference/update-pull-request.md) accept `parentPullRequest`, a selector that names the stack parent by `number` or `id`, or removes it with `clear` on update. Exactly one member must be set; an empty selector, `clear: false`, more than one member, and `clear` on create each return `InvalidArgument` (HTTP 400). The edit is an association only: no branch is rewritten, and `base` is retargeted only when it is sent too. Update applies it after `base`, so an explicit parent wins over the one a base change derives.
- **Added.** [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md) accepts `stackId`, a stack id as returned in `stack.id`. It returns that stack's members in the requested sort order rather than stack order, so rebuild the stack from each member's `stack.parentPullRequest`. `state` still defaults to `open`, so pass `state=all` for the whole stack. A well-formed id that names no stack in the repository returns an empty list, and any other value returns `InvalidArgument` (HTTP 400).
- **Added.** [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md) accepts `headSha`, the full 40- or 64-character hex SHA of a pull request head. It selects a pull request when any of its recorded versions has that head commit, current or superseded, so compare `head.sha` on each result to tell the two apart. Malformed, abbreviated, and unknown SHAs match nothing.

### Check runs

- **Deprecated.** `checkRuns` on the [Batch Upsert Check Runs](https://cursor.com/docs/api/origin/reference/batch-upsert-check-runs.md) response is deprecated in favor of `results[].checkRun` and will be removed in a future release. It is still populated with the same runs in the same order. Migration: read `results[].checkRun`, which pairs each stored run with the `outcome` of its write.
- **Added.** [Post Check Run](https://cursor.com/docs/api/origin/reference/post-check-run.md) returns `outcome` and [Batch Upsert Check Runs](https://cursor.com/docs/api/origin/reference/batch-upsert-check-runs.md) returns `results[]`, one per posted run in request order, each pairing `checkRun` with its own `outcome`. The value is `created`, `updated`, `unchanged`, or `ignored_stale`. A post whose `externalUpdatedAt` is older than the stored stamp is ignored, and a post that repeats the stored values changes nothing; both answer `200` with the stored run and leave `updatedAt` where it was, so `outcome` is the only way to tell them apart.
- **Changed.** A check run annotation `message` can contain Markdown, which Origin renders on the pull request page in both the Checks tab and the inline card on Changes. Accepted on [Post Check Run](https://cursor.com/docs/api/origin/reference/post-check-run.md) and [Batch Upsert Check Runs](https://cursor.com/docs/api/origin/reference/batch-upsert-check-runs.md), and returned by [Get Check Run](https://cursor.com/docs/api/origin/reference/get-check-run.md). `rawDetails` stays plain text.

### Git data

- **Changed.** [Get Git Commit](https://cursor.com/docs/api/origin/reference/get-git-commit.md) resolves an abbreviated `sha` only when it has at least 5 hex characters, and only among commit objects; the request fails when no commit or more than one commit carries the abbreviation. Full SHAs, branches, tags, and `HEAD` resolve as before.

### SSH certificate authorities

- **Added.** [List SSH Certificate Authorities](https://cursor.com/docs/api/origin/reference/list-ssh-certificate-authorities.md) lists the SSH certificate authorities an owner trusts for git over SSH, newest first, together with `requireCertificates`, whether the owner requires certificates: `GET /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities`. The response is not paginated, and each `certificateAuthorities[]` entry carries `id`, `name`, `keyType`, `fingerprint`, `publicKey`, and `createdAt`. Requires [`namespace:settings:read`](https://cursor.com/docs/api/origin/reference/scopes.md).
- **Added.** [Add SSH Certificate Authority](https://cursor.com/docs/api/origin/reference/add-ssh-certificate-authority.md) adds an authority the owner trusts and returns it: `POST /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities`. The body takes a required `publicKey`, one OpenSSH `authorized_keys` line whose key type is `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, or `ssh-rsa` with a modulus of at least 2048 bits, and a required `name` of at most 255 characters. A certificate, an unsupported key type, or a shorter RSA key returns `InvalidArgument` (HTTP 400); a key the owner already lists returns `AlreadyExists` (HTTP 409 Conflict), with the check scoped to the owner rather than to Origin as a whole; and an owner that is not team-owned returns `FailedPrecondition` (HTTP 400). Requires a Cursor user credential holding [`namespace:settings:write`](https://cursor.com/docs/api/origin/reference/scopes.md).
- **Added.** [Delete SSH Certificate Authority](https://cursor.com/docs/api/origin/reference/delete-ssh-certificate-authority.md) removes an authority from the owner and answers `204 No Content`: `DELETE /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities/{certificateAuthorityId}`. Every certificate the authority signed stops working, and while the owner requires certificates its last authority cannot be removed, which returns `FailedPrecondition` (HTTP 400). Requires a Cursor user credential holding [`namespace:settings:write`](https://cursor.com/docs/api/origin/reference/scopes.md).
- **Added.** [Set SSH Certificate Requirement](https://cursor.com/docs/api/origin/reference/set-ssh-certificate-requirement.md) sets whether the owner requires SSH certificates: `POST /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities:setRequirement`. The body takes a required `requireCertificates` boolean, and the response carries the owner's `requireCertificates` setting. While required, git over SSH on the owner's repositories accepts only certificates from the owner's authorities, so SSH keys registered by users and user API keys over HTTPS are refused. Requiring certificates with no listed authority returns `FailedPrecondition` (HTTP 400), and setting the current value succeeds without change. Requires a Cursor user credential holding [`namespace:settings:write`](https://cursor.com/docs/api/origin/reference/scopes.md).

### Webhooks

- **Added.** [`pull_request.comment.reaction.added`](https://cursor.com/docs/api/origin/reference/events.md) and [`pull_request.comment.reaction.removed`](https://cursor.com/docs/api/origin/reference/events.md) are subscribable webhook events, delivered when a reaction is placed on or removed from a pull request comment. Their shared [payload](https://cursor.com/docs/api/origin/reference/pull-request-comment-reaction-events.md) carries the `pullRequest` reference, a `comment` reference with its `thread`, and the `reaction` with its `content` and `reactor`. An add is delivered at least once: re-placing a reaction the reactor already holds delivers the event again for the same comment, reactor, and content, so fold on that triple. Removing a reaction the reactor does not hold delivers nothing.
- **Changed.** The [`pull_request.label.removed`](https://cursor.com/docs/api/origin/reference/events.md) [payload](https://cursor.com/docs/api/origin/reference/pull-request-label-events.md) carries `actor`, the principal that removed the label, when known. The [September 19](https://cursor.com/docs/api/origin/changelog.md#sep-19-2026) entry described `actor` as set on `pull_request.label.added` only; it is set on both events when the principal is known.

## September 19, 2026

- **Added.** [Delete Git Ref](https://cursor.com/docs/api/origin/reference/delete-git-ref.md) deletes a branch reference: `DELETE /v1/origin/repos/{ownerSlug}/{repoName}/git/refs/{ref}`. The path names the branch as `refs/heads/<branch>` or `heads/<branch>`, and only branch references can be deleted. A branch that does not exist returns `404`; the repository default branch, a branch a deletion rule protects, and a repository whose contents are mirrored from another host each return `FailedPrecondition` (HTTP 400); and a branch whose tip moves while the delete is in flight returns `FailedPrecondition` (HTTP 400) or `Aborted` (HTTP 409 Conflict), so retry to delete the new tip. Pull requests whose head is the deleted branch are closed, as after a pushed deletion. Requires [`repository:contents:write`](https://cursor.com/docs/api/origin/reference/scopes.md) and costs 5 points.
- **Added.** [`pull_request.label.added`](https://cursor.com/docs/api/origin/reference/events.md) and [`pull_request.label.removed`](https://cursor.com/docs/api/origin/reference/events.md) are subscribable webhook events, delivered when a label is assigned to or unassigned from a pull request. Their shared [payload](https://cursor.com/docs/api/origin/reference/pull-request-label-events.md) carries the `pullRequest` reference and the `label` snapshot, plus an `actor` naming the principal that assigned the label on `pull_request.label.added` only. Deleting a label definition delivers one `pull_request.label.removed` for every pull request that carried the label.

## September 18, 2026

- **Breaking.** [Create App](https://cursor.com/docs/api/origin/reference/create-app.md) enforces the namespace owner's eligibility to write to Origin, the same precondition [Create Repo](https://cursor.com/docs/api/origin/reference/create-repo.md) has always carried. A request against a namespace whose user owner is not on a Pro, Pro Student, Pro+, Ultra, or Start plan, or whose team owner lacks an active paid team plan, sits on Privacy Mode (Legacy), or has Origin turned off by a team admin, returns `FailedPrecondition` (HTTP 400) where it previously created the app. The check reads the namespace owner's eligibility, not the calling user's. Migration: create apps only under namespaces whose owner can write to Origin, and handle `FailedPrecondition` wherever your integration assumed the app was created.
- **Changed.** Origin allows a webhook receiver 10 seconds to answer a delivery, up from five seconds. The deadline covers DNS resolution, the connection, the TLS handshake, and the time to the response, and it applies to every attempt; an attempt that passes it counts as a transport error and is retried on the schedule [Retries](https://cursor.com/docs/api/origin/reference/retries.md) documents.

## September 17, 2026

- **Breaking.** [Get Repo Tarball](https://cursor.com/docs/api/origin/reference/get-repo-tarball.md) archives wrap the repository tree in a single top-level directory named `{ownerSlug}-{repoName}-{shortSha}/`, where `shortSha` is the first 7 hex characters of the resolved commit, matching the layout of GitHub's tarball endpoint. Archive entries previously sat at the root of the tar with no wrapping directory. Migration: strip one leading path component when extracting, for example `tar --strip-components=1`, wherever your integration read entries from the tar root.
- **Breaking.** [Get App](https://cursor.com/docs/api/origin/reference/get-app.md) requires [`namespace:apps:read`](https://cursor.com/docs/api/origin/reference/scopes.md) on the app's owning namespace in place of `app:settings:read`, the scope announced with the endpoint in the [September 12](https://cursor.com/docs/api/origin/changelog.md#sep-12-2026) entry. `app:settings:read` no longer authorizes anything and has been removed from the scope catalog; `app:settings:write` is unchanged and still covers [Update App](https://cursor.com/docs/api/origin/reference/update-app.md), [Add App Signing Key](https://cursor.com/docs/api/origin/reference/add-app-signing-key.md), and [Revoke App Signing Key](https://cursor.com/docs/api/origin/reference/revoke-app-signing-key.md). Migration: hold `namespace:apps:read` on the app's owning namespace wherever your integration held `app:settings:read`.
- **Added.** [List App Installation Repositories](https://cursor.com/docs/api/origin/reference/list-app-installation-repositories.md) accepts `filter`, a case-insensitive substring match applied to repository names and owner namespaces. A single-slash `owner/repo` value matches each half against its corresponding field, leading and trailing whitespace is ignored, and an empty value applies no filter. A page token carries the filter it was minted under, so send the same filter when requesting subsequent pages.
- **Changed.** The [OpenAPI specification](https://cursor.com/docs/api/origin/openapi.yaml) no longer stamps `format: enum` on string enum schemas. The key is not a registered OpenAPI or JSON Schema format, it duplicated the `enum` list beside it, and generators that mapped it to a named type emitted code that does not compile. Schema names, enum values, and the JSON on the wire are unchanged; regenerate any client built from the specification to pick up the corrected types.

## September 16, 2026

- **Breaking.** The [`repository.check_run.created`](https://cursor.com/docs/api/origin/reference/events.md) and [`repository.check_run.completed`](https://cursor.com/docs/api/origin/reference/events.md) [payloads](https://cursor.com/docs/api/origin/reference/check-run-events.md) no longer carry a payload-level `actor`. It repeated the owning check suite's principal, which the same payload already delivers as `checkSuite.actor` and `checkRun.actor`. Migration: read `checkRun.actor`, which always equals the owning suite's `actor`, wherever your integration read the payload's top-level `actor`.
- **Breaking.** `caseInsensitive` and `wholeWord` on [Grep Contents](https://cursor.com/docs/api/origin/reference/grep-contents.md) apply only when `literal` is true. A regular-expression search ignores both booleans where it previously honored them, and a `query` of only `(?i)` returns `InvalidArgument` (HTTP 400). Migration: set `literal` to keep using the booleans, or for a regular-expression search write a leading `(?i)` and `\b` word bounds into `query` instead.
- **Breaking.** The [OpenAPI specification](https://cursor.com/docs/api/origin/openapi.yaml) renames the `Thread` component schema to `CommentThread`. It is the response schema of [Update Pull Request Thread](https://cursor.com/docs/api/origin/reference/update-pull-request-thread.md) and the type of the `thread` object on a pull request comment. Field names, paths, operation IDs, and the JSON on the wire are unchanged, so an integration that reads the responses directly needs no change. Migration: regenerate any client built from the specification, and rename the type wherever generated code named `Thread`.
- **Added.** [Add App Installation Repositories](https://cursor.com/docs/api/origin/reference/add-app-installation-repositories.md) adds repositories to an existing installation's selection and returns the updated installation: `POST /v1/origin/namespaces/{namespaceSlug}/installations/{installationId}/repos`. The body takes a required `repoIds` array, which is unioned with the current selection; the write never changes the installation's scopes, and a request whose repositories are all already granted succeeds without changing anything. A repository outside the namespace, an installation that already covers every repository in the namespace, a suspended installation, and one that predates per-installation scopes each return `FailedPrecondition` (HTTP 400) and grant nothing. Requires a Cursor user credential holding [`namespace:installations:write`](https://cursor.com/docs/api/origin/reference/scopes.md) and costs 5 points. A first install still needs a namespace admin's consent in the browser.
- **Added.** Charged [Git over HTTPS](https://cursor.com/docs/api/origin/reference/git-https-authentication.md) responses carry `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Used`, with `X-RateLimit-Resource` set to `git`. - **Added.** [List Pull Requests](https://cursor.com/docs/api/origin/reference/list-pull-requests.md) takes five more query parameters: `author`, a public actor ID exactly as the response returns it in `pullRequests[].author.user.id`, `pullRequests[].author.app.id`, or `pullRequests[].author.serviceAccount.id`; `base`, an exact base-branch filter that accepts a short name or a fully qualified ref; `direction`, `desc` for newest first (the default) or `asc` for oldest first; and `since` and `until`, inclusive RFC 3339 bounds on creation time. An author with no pull requests returns an empty list, and any other unusable value returns `InvalidArgument` (HTTP 400).
- **Added.** [`pull_request.review.dismissed`](https://cursor.com/docs/api/origin/reference/events.md) is delivered when a submitted review is dismissed, whether explicitly or by being superseded by a newer decision. It carries the same [payload shape](https://cursor.com/docs/api/origin/reference/event-payloads.md) as `pull_request.review.submitted` with `review.dismissal` populated, and subscribing to it needs [`repository:pull_requests:reviews:read`](https://cursor.com/docs/api/origin/reference/scopes.md).
- **Added.** Installations name the user who installed the app. `installedBy`, carrying that user's public `user_…` ID and email, is returned by [Get App Installation](https://cursor.com/docs/api/origin/reference/get-app-installation.md) and [List App Installations](https://cursor.com/docs/api/origin/reference/list-app-installations.md) and rides every `installation.*` [webhook snapshot](https://cursor.com/docs/api/origin/reference/event-payloads.md); there it identifies the original installer and is omitted when that user record can no longer be read. The [installation receipt](https://cursor.com/docs/api/origin/reference/installation-receipt.md) gains an `installedBy` claim naming the user who performed that install or re-consent, so after a re-consent the two can differ.

## August 25, 2026

- **Added.** [Ping Webhook](https://cursor.com/docs/api/origin/reference/ping-webhook.md) sends a test delivery to your app's configured webhook URL and reports what the receiver answered: `POST /v1/origin/app/webhook/pings`. The delivery is signed like a production one, carries `webhook-event-type` of `ping`, and belongs to no installation. Origin sends it once with no retries, and it never appears in [List Webhook Deliveries](https://cursor.com/docs/api/origin/reference/list-webhook-deliveries.md). An app with no webhook URL configured is rejected with `FailedPrecondition` (HTTP 400).
- **Added.** Error responses carry the request ID twice: an `X-Request-ID` response header, and a `google.rpc.RequestInfo` entry in `details`. Origin echoes the `x-request-id` you sent or generates one when you send none, and includes the entry even when the message is an opaque internal error. See [Errors](https://cursor.com/docs/api/origin/reference/errors.md).
- **Changed.** [Create Pull Request](https://cursor.com/docs/api/origin/reference/create-pull-request.md) and [Update Pull Request](https://cursor.com/docs/api/origin/reference/update-pull-request.md) reject a `title` longer than 256 characters, or a `body` longer than 65,536 characters, with `InvalidArgument` (HTTP 400). Values past those lengths previously failed with an internal error. Both limits count Unicode code points, so an astral character such as an emoji counts once.
- **Changed.** [Sync Mirror](https://cursor.com/docs/api/origin/reference/sync-mirror.md) responses always carry `synced`, `true` or `false`, mirroring the HTTP status: `200` when true, `202` when false. The field was previously omitted when false, so callers had to read an absent field as `false`.
- **Changed.** Unmatched paths under `/v1/origin`, and requests that use the wrong method on a known path, return the documented [error envelope](https://cursor.com/docs/api/origin/reference/errors.md) rather than a generic router body. The message names the method and path and never echoes the query string.
- **Changed.** Merging a pull request delivers a [`repository.pushed`](https://cursor.com/docs/api/origin/reference/events.md) webhook for the base ref the merge advances. Origin performs that push itself, so the event names no pusher. Base-ref updates from a merge were previously not delivered.

## August 22, 2026

- **Added.** [Delete Ruleset](https://cursor.com/docs/api/origin/reference/delete-ruleset.md) deletes a repository ruleset by its stable Origin ID and returns `204`: `DELETE /v1/origin/repos/{ownerSlug}/{repoName}/rulesets/{rulesetId}`. Requires [`repository:rulesets:write`](https://cursor.com/docs/api/origin/reference/scopes.md). A ruleset stored on a different repository reads as an unknown ruleset, and an empty `rulesetId` is rejected with `InvalidArgument` (HTTP 400).
- **Added.** Every repository-scoped endpoint addresses a repository by its stable ID as well as by owner and name: send `_` as the owner slug and the ID as the repository name, as in `GET /v1/origin/repos/_/REPO_ID`. [Create Repo](https://cursor.com/docs/api/origin/reference/create-repo.md) takes an owner slug alone and rejects `_`.

- **Added.** [List Rulesets](https://cursor.com/docs/api/origin/reference/list-rulesets.md) returns every ruleset configured on a repository plus one shared `repository` reference: `GET /v1/origin/repos/{ownerSlug}/{repoName}/rulesets`. - **Added.** [Create Ruleset](https://cursor.com/docs/api/origin/reference/create-ruleset.md) stores a new ruleset and returns it with the IDs Origin assigns to each rule and bypass actor: `POST /v1/origin/repos/{ownerSlug}/{repoName}/rulesets`. - **Added.** [Get Ruleset](https://cursor.com/docs/api/origin/reference/get-ruleset.md) returns a single ruleset by its stable Origin ID: `GET /v1/origin/repos/{ownerSlug}/{repoName}/rulesets/{rulesetId}`.
- **Added.** [Update Ruleset](https://cursor.com/docs/api/origin/reference/update-ruleset.md) replaces a ruleset's configuration in full, including its `rules` and `bypassActors`: `PUT /v1/origin/repos/{ownerSlug}/{repoName}/rulesets/{rulesetId}`. Send every rule and bypass actor you want to keep, because the stored entries are replaced rather than merged.
- **Added.** Rulesets carry `id`, `name`, `description`, `enforcement` (`active`, `evaluate`, or `disabled`), `kind` (`merge_branch`, `push_branch`, `push_tag`, or `push_repository`), the `includedRefNames` and `excludedRefNames` patterns that accept globs plus the `~ALL` and `~DEFAULT_BRANCH` tokens, `rules`, and `bypassActors`. [Create Ruleset](https://cursor.com/docs/api/origin/reference/create-ruleset.md) and [Update Ruleset](https://cursor.com/docs/api/origin/reference/update-ruleset.md) reject more than 64 patterns per list, 20 rules, or 15 bypass actors with `InvalidArgument` (HTTP 400).
- **Added.** [Merge Pull Request](https://cursor.com/docs/api/origin/reference/merge-pull-request.md) accepts an optional `expectedHeadSha` request field, the full commit SHA the pull request's head must match. When the head has moved, the merge is rejected with `ABORTED` (HTTP 409 Conflict) and nothing merges; a value that is not a full commit SHA is rejected with `InvalidArgument` (HTTP 400). Omit it to merge whatever the current head is.
- **Added.** Owner references carry a `type` string, `team` or `user`, omitted when Origin cannot resolve it. Returned wherever an `owner` or installation `target` appears, including [Get Repo](https://cursor.com/docs/api/origin/reference/get-repo.md), [List Repos](https://cursor.com/docs/api/origin/reference/list-repos.md), [List App Installations](https://cursor.com/docs/api/origin/reference/list-app-installations.md), and the repository reference on check and pull request responses.
